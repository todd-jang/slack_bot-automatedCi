# Slack Bot with Waypoint Prediction

## Overview

This repository implements a **Slack Bot** that can trigger machine‑learning workflows for trajectory (way‑point) prediction.  The core components are:

- **Slack Bolt app** (`bot.py`) – receives slash‑commands and dispatches tasks.
- **Dataset generation** (`dataset/`) – synthetic data for training a simple feed‑forward model.
- **Training script** (`train_fsd.py`) – trains a model to predict future way‑points.
- **Inference script** (`inference_fsd.py`) – loads the best checkpoint and runs predictions on synthetic or real samples.
- **PID controller** (`controller/pid.py`) – demo controller that follows the predicted way‑points.
- **GitHub Actions CI** (`.github/workflows/ci.yml`) – validates the pipeline on each push/PR, checking that training runs, inference latency meets an ultra‑low‑latency target, and the controller executes without errors.

All code lives under the **`slack-bot`** directory:
```
/slack-bot
├─ bot.py                # Slack Bolt entry point
├─ train_fsd.py          # Model training
├─ inference_fsd.py      # Model inference
├─ controller/
│   └─ pid.py           # Simple PID demo
├─ dataset/
│   └─ synthetic.py     # Synthetic data generator
├─ models/               # Saved checkpoints (e.g., fsd_v1.pth)
└─ .github/workflows/ci.yml  # CI pipeline
```

## Setup

1. **Clone the repository**
   ```bash
   git clone https://github.com/your‑org/slack‑bot.git
   cd slack‑bot
   ```
2. **Create a virtual environment & install dependencies**
   ```bash
   python3 -m venv venv
   source venv/bin/activate   # macOS/Linux
   # or `venv\Scripts\activate` on Windows
   pip install -r requirements.txt
   ```
   The `requirements.txt` contains `torch`, `slack‑bolt`, and other helper libraries.

3. **Configure Slack credentials**
   - Create a Slack App at <https://api.slack.com/apps> with the required scopes (`commands`, `chat:write`).
   - Add the **Bot Token** and **Signing Secret** to a `.env` file:
   ```env
   SLACK_BOT_TOKEN=xoxb-...
   SLACK_SIGNING_SECRET=...
   ```
   The bot reads these variables automatically via `python‑dotenv`.

## Running the Bot

```bash
source venv/bin/activate
python bot.py
```
The bot will start a local server (default `http://localhost:3000`). Use ngrok or a similar tunneling service to expose the endpoint to Slack and set the request URL in the Slack App configuration.

## Training the Model

```bash
source venv/bin/activate
python train_fsd.py \
    --epochs 10 \
    --batch-size 32 \
    --num-samples 5000   # increase for better generalisation
```
- The script saves the best checkpoint as `models/fsd_v1.pth`.
- Validation now reports **Mean‑L2‑Distance (MSE) loss** only.

## Inference

```bash
source venv/bin/activate
python inference_fsd.py \
    --checkpoint models/fsd_v1.pth \
    --samples 5          # run on a few synthetic samples
```
The script prints predicted way‑points and the average inference latency. Adjust `--latency-threshold` if you need a stricter bound.

## PID Controller Demo

The `controller/pid.py` script demonstrates a simple proportional‑integral‑derivative loop that consumes the way‑points produced by the model and generates steering/throttle commands.

```bash
source venv/bin/activate
python controller/pid.py \
    --checkpoint models/fsd_v1.pth \
    --duration 10        # seconds of simulation
```
Feel free to tune `Kp`, `Ki`, and `Kd` via command‑line arguments.

## Continuous Integration (CI)

The repository includes a GitHub Actions workflow (`.github/workflows/ci.yml`) that:
1. Sets up Python and installs dependencies.
2. Runs a quick training pass to ensure the code compiles.
3. Executes `inference_fsd.py` on a handful of samples and asserts that the average latency stays below the ultra‑low‑latency threshold (default ≤ 5 ms).
4. Runs the PID demo to verify end‑to‑end execution.

Any push or pull‑request will automatically trigger this pipeline. Failures block merges, guaranteeing that the bot, model, and controller remain functional.

## Adding Real Data

To replace the synthetic generator with real telemetry:
1. Place your dataset in `dataset/real/` (CSV or Parquet) with columns `cam`, `lidar`, and `waypoints`.
2. Update `dataset/__init__.py` to load the real data when `--use-real` flag is passed.
3. Re‑run `train_fsd.py` with `--use-real` and increase `--num-samples` accordingly.
